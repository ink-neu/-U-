# 人工智障勇闯U校园

> 一次关于「用工程手段解决本来不用解决的问题」的技术复盘

## 引言

这是一份关于「怎么把一门大学英语视听说教程刷到 90 分以上」的技术复盘。

先说结论：

> 愿意花 5 块钱，就不要使用这个。

5 块钱能解决的事情，这里花了 65 个脚本、几十个小时、一个从不敢关闭的 Chrome 窗口、28 段被语音评测系统判 44 分的合成人声，以及若干次「UI 显示 100 分，服务器其实还是 66.7 分」的深夜返工。

项目名里的「人工智障」不是自谦，是实测结论：它会把一道三选一的选择题做成只读勘查、答案溯源、双页面兜底、提交前硬校验、服务器二次复核五个步骤，然后在第 4 步因为页脚按钮的文字里多了一个空格而找不到「提 交」。

但作为一次工程练习，它确实跑通了：6 个单元、79 个目录节点，U1/U2 重刷后 41 项计分题全部 ≥90，低于 90 的项目为 0。所以这个文件留下的是方法、数据和教训 —— 尤其是教训。

---

## 优点

- **只读优先，先审计再动手** — 每轮开工先跑只读勘查，确认节点是「可作答 / 解析锁定 / 小结」哪种状态，再拉服务器版本化记录看真实分数。前后两次纠正了「全书 90–100」的误报——那都是本地 UI 缓存给出的假象。

- **答案零猜测** — 标准答案来自平台自身下发的答卷与答题解析，不从搜索引擎找、不让模型蒙。选择题、填空题、排序题、朗读原文全部可溯源，这是「一遍过」成立的前提。

- **提交前硬校验** — 选项下标、填空值、拖拽后的最终顺序、每条录音的分数，提交前一律二次回读；任何一项不匹配直接抛错拒绝提交。整个 U1/U2 重刷没有一次靠试错换答案。

- **录音设 90 分闸门** — 跟读 / 朗读 / 配音题，只要有一条低于 90 分就不提交，继续重录。重录不消耗提交机会，所以可以安全地穷举发音变体；同时读准确度、流利度、完整度三项细项分，定位到底是发音问题还是被截断了半句话。

- **全程不关闭用户浏览器** — 通过调试端口连接常驻浏览器。中途掉线只重启调试通道；某个空白页卡死也只关那一个标签，原有页面与登录态保持不动。

- **提交后必回服务器复核** — 本地小结显示 100 分不算完成，必须再读一次服务端记录。正是这条规则发现了几处「本地满分、服务器仍低分」的假成功。

- **结果全部可追溯** — 95 个题目组、每题前后分数、作答内容、是否必修、是否计入成绩，都落在本地 JSON 里，可随时重算，不依赖页面当前显示。

- **最终成绩确实达标** — U1：20 项计分题，均值 99.38，最低 93.14；U2：21 项，均值 99.36，最低 90.67。两单元低于 90 分的项目数为 0。

## 缺点

- **合规与学术诚信 —— 这是最大缺点** — 本质是自动代答、代录音，绕过课程的评测环节。它可能违反平台服务条款与学校的教学管理规定，成绩存在被认定无效的风险，账号也有风险。它不产生任何学习效果，不该被当作学习工具，更不该替别人完成课程。

- **公开版根本不能刷课** — 正因为上一条，上传 GitHub 的这个版本不包含平台连接、自动填答与提交、答案解密、模拟麦克风等任何可执行实现。clone 下来只有文档、统计与复盘。想要「能跑的」，就得自己承担相应后果——本项目不提供。

- **投入产出比荒谬** — 65 个脚本、几十个小时、几十个 TTS 发音候选、多轮本地语音转写和视频逐帧比对，换来的只是几道平时成绩练习题。「愿意花 5 块钱就不要使用这个」不是段子，是本项目的成本结论。

- **平台只认第一次作答** — 客观题的得分只记录首次提交，事后用正确答案重刷不会覆盖。因此有若干历史低分（如 U3 判断题 75、U4 填空 62.5）永久锁定，只能如实记为不可修；所幸这两项都不计入成绩。

- **语音评测是黑盒且极不稳定** — 同一句英文，换个合成嗓音分数能在 44 到 95 之间跳；有时只有一半词被识别（完整度 50）。没有可解释的规律，只能靠批量生成变体逐个试，属于典型的用算力换运气。

- **链路非常脆弱** — 登录票据是一次性的，播放器页不能刷新，只能绕目录重新进入；调试端口会掉，页面一改版全部选择器作废；题目组 id、标签路径大量硬编码；接口参数还会随日期变化。任何一环变动都要重写。

- **本地显示 ≠ 服务器记录** — 页面小结可能是过期缓存，「查看答题小结」也可能读到诊断页残留。曾经据此得出「已修到 100」的错误结论，必须单独复核服务端数据才作数。

- **0 分不一定是低分** — 不评分的主观题在平台记录里默认就是 0 分。只看分数会把 20 道正常提交的讨论题误判成待修项，得结合计分标记才能区分。

- **环境零可移植性** — Windows + 固定调试端口的 Chrome + Playwright / edge-tts / faster-whisper / pycryptodome / imageio-ffmpeg，外加特定课程版本的目录结构。换台机器基本等于重做一遍。

- **无人值守有硬边界** — 登录失效、验证码、平台限流、接口频率限制都会让流程停摆，仍然需要人工回来处理。「自动」只是大部分时候自动。

- **隐私与凭据风险** — 本地数据目录里含成绩、课程标识、会话凭据与录音文件。上传前必须排除，否则等于把账号信息一起 push 上去。--init 会生成对应的 .gitignore。

- **没有泛化能力** — 所有逻辑都贴着这一门课、这一版页面写死。换教材、换平台、甚至只是改了一个 CSS 类名，整套东西就得重新来过——它解决的是一个具体问题，不是一类问题。

## 踩过的坑

- 播放器页不能 reload（登录票据一次性），刷新状态一律走目录重新进入节点。
- 页脚「提 交」的文字常带空格且不是叶子节点，叶子文本匹配会失效，要用类名或坐标兜底。
- 多数客观题与拖拽题要求媒体播放结束才能提交，先把进度拖到结尾并等 ended。
- 拖拽题每一步都要回读顺序，插入语义不稳定；最终顺序不等于目标顺序就拒绝提交。
- 口语题提交无反应时，重新进入节点比反复点击有效。
- 答错一次就可能被锁定 —— 所以「只读勘查 → 答案溯源 → 一次提交」是唯一合理顺序。
- 不评分主观题显示 0 分，要看计分标记，别当成低分去刷。

## 用法

```bash
python 人工智障勇闯U校园.py            # 打印完整自述
python 人工智障勇闯U校园.py --init     # 重新生成 README.md 与 .gitignore
python 人工智障勇闯U校园.py --stats    # 统计本地成绩数据
python 人工智障勇闯U校园.py --self-test
```

仅依赖 Python 3.9+ 标准库，无需安装任何第三方包。若终端对中文文件名支持不佳，把文件重命名为 `main.py` 后运行即可（`--init` 生成的 README 标题不受影响）。

## 结论

工程上它跑通了；作为一件产品，它是一次失败——成本远高于收益，且用途本身就不站得住脚。**愿意花 5 块钱，就不要使用这个。**
